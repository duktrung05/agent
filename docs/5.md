# Bài 3 — Tool calling

**Mục tiêu:** Thấy model đề xuất gọi hàm và Python thực thi hàm thật.

## Chạy

Tại dấu `$` của Bash:

```bash
python3 lessons/03_tool_calling.py
```

Khi chương trình hiện `Bạn>`, chỉ nhập câu hỏi, không gõ thêm dấu nhắc:

```text
Tìm 3 bài báo PubMed về mối liên hệ giữa giấc ngủ và Alzheimer.
```

`/bye` để thoát. Mỗi câu hỏi bắt đầu một phiên riêng; chưa có memory hội thoại.
Không cần cài package Python ngoài. Model chạy local, PubMed cần Internet.

## Ba phần cần đọc trong code

| Phần | Công việc |
|---|---|
| `PUBMED_TOOL` | Mô tả tên hàm, khi dùng, kiểu tham số và giới hạn cho model |
| `execute_tool()` | Kiểm tra tên/kiểu/giới hạn rồi gọi lại hàm bài 2 |
| `run_question()` | Gửi schema → nhận tool call → thực thi → đưa kết quả về model |

```text
Bạn hỏi → model trả tool_calls → Python kiểm tra → gọi PubMed
         → thêm role=tool vào messages → model đọc kết quả
```

**Schema là bản mô tả. Model không tự chạy Python.**
Tool call có thể có `content` rỗng; cần đọc `message.tool_calls`.

## Quan sát terminal

1. Tool được công bố.
2. Tên hàm và tham số model thực sự yêu cầu.
3. Kết quả PubMed do Python gọi, hoặc lỗi nguồn.
4. Câu trả lời sau khi model nhận kết quả.

**Nhánh lỗi nguồn:** Nếu tool trả `ok=false`, Python báo lỗi và dừng lượt đó,
không gọi model lần cuối. Không được biến “chưa lấy được dữ liệu” thành
“không có bài báo”. Đây là gate bằng code, không chỉ là một câu nhắc trong prompt.

Chỉ có PMID/count ở bài này. Model chưa đọc abstract nên không được coi câu trả lời
là tổng hợp kết quả nghiên cứu. Luôn đối chiếu lời model với JSON tool.

## Bài tự thử

- Hỏi `Agent AI là gì?`: quan sát model có tránh gọi PubMed không.
- Hỏi tìm bài về COPD: quan sát query thay đổi, không sửa Python theo bệnh.
- Xem riêng schema: `python3 lessons/03_tool_calling.py --show-schema`.

Một câu hỏi tối đa một tool call và hai lượt model; không tự gọi lại model hay chuyển cloud.
Riêng request đọc ESearch có tối đa một lần retry sau 1 giây cho lỗi tạm thời/JSON hỏng.
Nếu model không gọi tool khi được yêu cầu tìm bài, xem phần `[2]`: không tự giả lập tool call.
Nếu output bị cắt, script dừng và báo lỗi thay vì thực thi tham số chưa hoàn chỉnh.

**Đạt khi:** Chỉ ra được đâu là schema, đâu là tool call model tạo và đâu là kết quả thực thi thật.

## Trạng thái kiểm chứng

- Đã đạt 7 kiểm thử client/executor bằng dữ liệu giả lập: tên/kiểu/giới hạn sai bị chặn,
  lỗi nguồn không thành kết quả rỗng, không gọi tool khi không có yêu cầu tool,
  gửi kết quả về đúng role, chặn nhiều tool, chặn output bị cắt và thoát bằng `/bye`.
- Đã chạy thật với `qwen3:1.7b`: model đề xuất `search_pubmed` với query
  `sleep AND Alzheimer's disease`, limit 3; Python gọi PubMed và model đọc lại 3 PMID.
- Lời diễn giải của model sau tool vẫn cần kiểm tra. Chỉ có PMID/count chưa chứng minh
  nội dung hoặc kết luận của từng bài báo. Chưa đánh giá chất lượng y khoa.
- Đã thêm regression cho trường hợp lỗi nguồn bị model diễn giải thành không có bài báo.
  Chạy: `python3 -m unittest discover -s tests -v`.
