# Bài 1 — Hiểu và gọi model API trên local

## 1. Phạm vi đã chốt

- Bạn là intern, đây là dự án agent đầu tiên; đã có chút kinh nghiệm LLM và RAG.
- Mục tiêu là học bản chất và cách xử lý lỗi, chạy local.
- Dữ liệu dùng PubMed trước. VIBioMIR và các nguồn khác sẽ được bổ sung sau.
- Ưu tiên model local. Nếu thử API trả phí, tổng ngân sách thử nghiệm phải dưới 5 USD.

Trong bài này chỉ làm một việc: gửi một yêu cầu tới model và đọc kết quả đúng cách.
Chưa có agent loop hoặc truy xuất PubMed trong script. Đây là lớp nền để sau đó
phân biệt lỗi HTTP, lỗi model, lỗi tool và lỗi điều phối.

## 2. API local vẫn là API

API là giao diện để các chương trình trao đổi yêu cầu và kết quả; không đồng nghĩa
với một dịch vụ trả phí trên Internet.

Trong bài này:

1. Python là client, đóng gói yêu cầu thành JSON.
2. Ollama là server trên máy bạn, nhận HTTP request.
3. Ollama chạy model đã tải về và trả kết quả.
4. Python đọc JSON response và kiểm tra các trường cần thiết.

Endpoint local là `http://127.0.0.1:11434/api/chat`, không yêu cầu API key.
Xem [giới thiệu API chính thức](https://docs.ollama.com/api/introduction).

Chạy model local không mất phí theo token cho nhà cung cấp API; vẫn dùng RAM, CPU/GPU,
ổ đĩa và điện. Tải runtime/model ban đầu cần mạng.

## 3. Chọn model khởi đầu

Điểm xuất phát: `qwen3:1.7b`. Trang model liệt kê bản Q4_K_M khoảng 1,4 GB
và khả năng hỗ trợ tools. Dung lượng tải không phải tổng RAM khi chạy;
context và runtime dùng thêm bộ nhớ. Xem [trang model](https://ollama.com/library/qwen3:1.7b).

Đây là model để học giao tiếp kỹ thuật, chưa được đánh giá chất lượng y khoa cho dự án.
Sẽ đo lại khả năng trả lời, tiếng Việt và gọi tool bằng các bài kiểm tra sau.

Trong môi trường agent đã kiểm tra: Linux, tổng RAM khoảng 15,5 GiB,
RAM khả dụng tại thời điểm kiểm tra khoảng 4,5 GiB; không có lệnh `nvidia-smi`
hay `ollama`. Đây không phải kết luận máy không có GPU.

Giới hạn ban đầu của bài: context 2048 token, output tối đa 128 token,
mỗi lần một request. Không nạp corpus vào model ở bước này.

## 4. Chuẩn bị Ollama

Hướng dẫn dưới đây dành cho Linux, thực hiện trong terminal của bạn.

Nếu chưa có Ollama, tải script cài đặt chính thức về file rồi chạy:

```bash
curl -fsSL https://ollama.com/install.sh -o /tmp/agent-ollama-install.sh
sh /tmp/agent-ollama-install.sh
ollama --version
```

Installer có thể yêu cầu quyền sudo để cài ở cấp hệ thống.
Xem [hướng dẫn Linux](https://docs.ollama.com/linux).

Kiểm tra server:

```bash
curl --noproxy '*' --fail-with-body --max-time 10 http://127.0.0.1:11434/api/tags
```

Nếu đã trả JSON, server đang chạy; bỏ qua lệnh `serve` bên dưới.
Nếu chưa có server, mở một terminal riêng và giữ nó chạy:

```bash
OLLAMA_NO_CLOUD=1 OLLAMA_HOST=127.0.0.1:11434 ollama serve
```

`OLLAMA_NO_CLOUD=1` tắt tính năng cloud cho tiến trình server này.
Xem [cấu hình local-only của Ollama](https://docs.ollama.com/faq#how-do-i-disable-ollamas-cloud-features).

Trong terminal khác, tải model rồi kiểm tra:

```bash
ollama pull qwen3:1.7b
ollama list
```

`GET /api/tags` chỉ liệt kê model đã có, không sinh câu trả lời.
Danh sách rỗng có thể có nghĩa server đã chạy nhưng chưa tải model.
Xem [tài liệu endpoint](https://docs.ollama.com/api/tags).

## 5. Gọi HTTP bằng curl trước

```bash
curl --noproxy '*' --fail-with-body --max-time 180 \
  http://127.0.0.1:11434/api/chat \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "qwen3:1.7b",
    "messages": [
      {"role": "system", "content": "Trả lời bằng tiếng Việt, ngắn gọn và rõ ràng."},
      {"role": "user", "content": "Giải thích HTTP request và HTTP response trong hai câu ngắn."}
    ],
    "stream": false,
    "think": false,
    "keep_alive": 0,
    "options": {"num_ctx": 2048, "num_predict": 128}
  }'
```

### Đọc từng phần

| Thành phần | Vai trò trong bài |
|---|---|
| URL | Địa chỉ server local và endpoint cần gọi |
| POST | Gửi body yêu cầu sinh câu trả lời; curl chọn POST khi có `-d` |
| Content-Type | Báo body được gửi ở dạng JSON |
| model | Tên model đã tải, cần khớp `ollama list` |
| messages | Các message đưa vào context của lần gọi này |
| system / user | Hướng dẫn chung và yêu cầu hiện tại |
| stream=false | Nhận một JSON hoàn chỉnh, thuận tiện học cách parse trước |
| think=false | Yêu cầu tắt thinking ở model hỗ trợ tùy chọn này |
| num_ctx | Cấu hình context window cho bài thử |
| num_predict | Giới hạn output token; không phải giới hạn toàn bộ request |
| keep_alive=0 | Giải phóng model khỏi bộ nhớ sau request; lần sau có thể phải tải lại |

Cấu trúc body/response: [Chat API](https://docs.ollama.com/api/chat).
Các tùy chọn context và bộ nhớ: [Ollama FAQ](https://docs.ollama.com/faq).

`stream=false` là lựa chọn có chủ đích để học HTTP/JSON trước streaming.
Request hiện tại không chứa retrieval, tool hay dữ liệu PubMed.

## 6. Đọc response

Tìm các trường sau, không cần học thuộc toàn bộ JSON:

- `message.content`: nội dung trả lời.
- `done`: request sinh nội dung đã hoàn tất chưa.
- `done_reason`: lý do kết thúc; chú ý `length` khi chạm giới hạn sinh.
- `prompt_eval_count`: số input token được server báo.
- `eval_count`: số output token được server báo.
- `total_duration`: thời gian phía server tính bằng nanosecond; khác với thời gian client đo.

HTTP 200 chỉ xác nhận request thành công ở lớp HTTP. Còn phải kiểm tra nội dung,
trạng thái hoàn tất và sau này là tiêu chí nghiệp vụ. `done=true` cũng không có nghĩa
câu trả lời đúng hoặc đầy đủ nếu đã chạm giới hạn output.

Không chuyển số ký tự thành token bằng một tỷ lệ cố định. Khi server không báo số token,
ghi nhận thiếu metric thay vì tự tạo số liệu.

## 7. Gọi từ Python

Đọc file [01_call_local_api.py](../lessons/01_call_local_api.py) theo thứ tự:

1. `main`: nhận các tham số từ terminal.
2. `payload`: tạo request bằng Python dict.
3. `--dry-run`: xem endpoint và JSON body trước khi gọi thật.
4. `call_model`: encode JSON thành UTF-8, gửi POST và đọc bytes trả về.
5. Parse JSON, kiểm tra lỗi và các trường cần thiết.
6. In câu trả lời kèm thời gian và token server cung cấp.

Chạy từ thư mục gốc repo, dùng thư viện chuẩn nên không cần cài package Python ngoài:

```bash
python3 lessons/01_call_local_api.py --dry-run
python3 lessons/01_call_local_api.py
python3 lessons/01_call_local_api.py --prompt 'Phân biệt model và agent trong hai câu.'
```

Script không tự retry, tự tải model hoặc tự chuyển sang API cloud. Ở bài đầu,
giữ một lần chạy tương ứng một lần gọi giúp việc quan sát lỗi rõ ràng.

Exit code: `0` khi hoàn tất theo kiểm tra giao tiếp; `1` khi có lỗi;
`2` khi output bị cắt do giới hạn sinh hoặc tham số CLI không hợp lệ.
Kết quả hoàn tất chưa phải điểm đánh giá nội dung.

## 8. Khi gặp lỗi, kiểm tra theo lớp

| Hiện tượng | Kiểm tra đầu tiên | Thao tác tiếp theo |
|---|---|---|
| Không kết nối được | Server, port, quyền kết nối | Gọi `/api/tags`, xem terminal chạy server |
| HTTP 404 | Endpoint và tên model | Đối chiếu `ollama list`, tải đúng model nếu thiếu |
| HTTP 400 | Body và tùy chọn có hợp lệ không | So với request curl tối thiểu |
| Timeout | Tải model, RAM, tốc độ sinh | Xem log, thử prompt/output ngắn hơn |
| Parse JSON lỗi | Body có phải một JSON hay các dòng streaming | Kiểm tra `stream=false` |
| Output rỗng hoặc bị cắt | Nội dung response và lý do kết thúc | Ghi lại lỗi, xem giới hạn output/thinking |
| Có câu trả lời nhưng sai | Dữ liệu và nội dung model được nhận | Sang bài grounding/eval; không kết luận là lỗi HTTP |

HTTP timeout không bảo đảm server đã hủy công việc. Kiểm tra trước khi gửi lại
để tránh nhiều request chồng nhau. Mã lỗi chính thức: [Ollama errors](https://docs.ollama.com/api/errors).

## 9. Bài tập cần tự làm

1. Chạy `--dry-run`; chỉ ra URL, method, headers và body ở đâu trong code.
2. Gọi thật một lần; ghi model, câu hỏi, câu trả lời, token, thời gian và trạng thái kết thúc.
3. Đổi sang một tên model chưa tải, ví dụ `--model lesson-model-does-not-exist`, rồi đọc lỗi.
4. Thử `--max-output 8`; kiểm tra `done_reason` và nội dung thay vì mặc định coi là hoàn chỉnh.
5. Giải thích vì sao script này mới là một lần gọi LLM, chưa có vòng lặp agent.

Hoàn thành bài khi bạn có một response thật, giải thích được đường đi của request
và tái hiện được ít nhất một trường hợp lỗi. Nếu chưa gọi được model, ghi rõ lớp đang lỗi.

## 10. Phần tiếp theo: PubMed trở thành tool

Sau bài 1, ta sẽ học riêng cách gọi API PubMed để tìm bản ghi rồi lấy metadata/abstract,
kiểm tra timeout, kết quả rỗng và định danh nguồn. Sau đó mới cho model yêu cầu gọi tool đó.
Xem [giới thiệu API NCBI](https://www.ncbi.nlm.nih.gov/home/develop/api/).

PubMed được dùng trước theo lựa chọn hiện tại. Nguồn VIBioMIR chưa được nạp vào repo này;
chỉ tìm thấy cấu hình ở repo bên cạnh, chưa thấy file corpus tại các đường dẫn cấu hình.

## 11. Thực nghiệm API trả phí, nếu cần sau này

Ngân sách tổng do người học đặt: **dưới 5 USD**. Bài này không chứa client trả phí.

Khi làm bài so sánh model API, sẽ chọn nhà cung cấp/model, xác minh giá hiện hành,
đặt ngân sách làm việc tối đa 4 USD để chừa khoảng dự phòng, giới hạn request/output,
ghi usage thực tế và dừng khi không có đủ thông tin kiểm soát chi phí.
Không tự chuyển từ local sang trả phí khi gặp lỗi. Một mức cảnh báo chi tiêu không
được coi là bằng chứng đã có cơ chế chặn chi tiêu.

## 12. Trạng thái kiểm chứng

- Đã chuẩn bị script và hướng dẫn request/response.
- Kiểm tra ban đầu trong môi trường thao tác chưa chạy inference thật. Sau đó người học đã cung cấp ảnh kết quả gọi local: `completed`, input 45 token, output 22 token, 6,142 giây. Đây là kết quả do người học chạy; câu trả lời vẫn chỉ có một câu dù yêu cầu hai câu.
- Dry-run và 7 kiểm thử với response/transport giả lập đã đạt: request UTF-8,
  output bị cắt, response lỗi/thiếu dữ liệu, HTTP 404, timeout không retry,
  dry-run không gọi model và CLI trả mã lỗi khi output bị cắt.
  Đây là kiểm tra client, không phải kiểm tra inference hay chất lượng model.
